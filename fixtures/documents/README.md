# Document fixtures

Small, fictional demo documents for playbook intake (`extractDocument`, CONTRACTS §15.5).
Everything here is generated by code; nothing is a real playbook and no person, school or
team is named. Each file is well under 200 KB.

| File | What it is | Expected extraction |
| --- | --- | --- |
| `demo-playbook.pdf` | 3 pages with a text layer: a play page ("Inside Zone Right", formation line, a sketch of seven circles and an arrow), a numbered "Play List" (8 plays), a "Terms" page with "Term — definition" lines | 3 pages, `textSource: 'pdf_text'`, no warnings |
| `demo-scan.pdf` | 1 page whose only content is a PNG of typed text: a stand-in for a scanned page, no text layer | `ocr: 'off'` → `textSource: 'none'`, warning "Page 1 has no text layer; OCR is off."; `ocr: 'auto'` with tesseract.js installed → `textSource: 'ocr'`, confidence about 0.95 |
| `demo-notes.txt` | 130 lines of install notes | 3 pages of 60 / 60 / 10 lines, `textSource: 'pdf_text'` |
| `demo-notes.docx` | the first 12 lines of the notes as paragraphs, in a minimal WordprocessingML package (stored zip, three parts) | 1 page through mammoth |

## How they are generated

`packages/media/src/test/document-fixtures.ts` builds all four with `pdf-lib` (MIT, dev
dependency) and `@napi-rs/canvas` (for the scanned-page PNG) and a 40-line stored-zip writer
for the `.docx`. The media test setup (`global-setup.ts`) writes them into
`.data/wt-c3/documents/` on every run (override with `FOOTBALLOS_MEDIA_TEST_DIR`), so the
tests never read this directory. The copies here exist for manual checks and for uploading
through the UI:

```
node packages/media/bin/media.mjs doc-fixtures fixtures/documents   # regenerate (dates are fixed; bytes are stable)
node packages/media/bin/media.mjs doc fixtures/documents/demo-playbook.pdf .data/wt-c3/out/playbook
node packages/media/bin/media.mjs doc fixtures/documents/demo-scan.pdf .data/wt-c3/out/scan --ocr auto
```

PDF metadata dates are pinned to 2026-01-01 so regenerating produces the same bytes.
