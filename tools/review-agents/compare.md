# Recheck one role after an iteration

Keep the first round's JSON, Markdown and screenshots. On the updated workspace run, for example, `tools/review-agents/run.sh coordinator round-2`. The role, mock identity, task IDs, task order, prompts and step-count convention must match round 1. Record the new checkout and any fixture or evidence-method difference.

1. Complete fresh landing expectations, the walkthrough and interview before consulting the previous findings. Save new screenshots. A clean mock session prevents another role's approvals or label edits from changing the task.
2. Open the supplied JSON for the same role in round 1. For **every** previous ID, revisit the original action on the corresponding role, route and element. Use the prior observation and expected behavior as the check. Repeat the relevant entry and exit steps even if the control was renamed or moved.
3. Give each prior ID exactly one disposition with current evidence and a short reason. **Resolved** means the expected result was positively verified. **Improved** means the same problem still occurs with lower impact or fewer steps. **Unchanged** means the problem was reproduced with comparable impact. **Regressed** means completion or impact worsened. Disappearance of a title, a shorter list, a cosmetic rename or the absence of a screenshot cannot establish resolution. If a fixture or runtime prevents a fair comparison, describe the blocker and withhold the comparison until there is evidence for a disposition.
4. Preserve earlier IDs on open findings even if their title, severity or rank changes. Omit a resolved ID from the active round-2 findings and retain it in the comparison. Give genuinely new findings the next unused role IDs above the round-1 maximum. Rank open findings using the current evidence.
5. In the run's scratch directory write `comparison.json` with `prior` and `new` arrays. A prior row has `id`, `status`, `reason` and a current-round `evidence` reference in protocol format. `new` contains the IDs of every new active finding. Both arrays may be empty. The launcher checks coverage and publishes `reports/round-2/<role>-comparison.md` alongside the regular reports. Cross-round statuses stay out of the shared active-findings schema.

Compare like with like when reporting step counts. An altered fixture, a source-only inference or an infrastructure failure cannot establish a better in-season experience.
